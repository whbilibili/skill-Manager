# Doc to HTML — 文档可视化转换技能

将文档转化为精美交互式 HTML 的核心原则：**可视化形式服务于内容，而非内容迁就形式**。每一个设计决策都应该让读者更容易理解内容，而不是为了"好看"而好看。

---

## Step 0：内容感知分析（必须先做，不要跳过）

在写任何代码之前，先完成这个分析并向用户展示你的判断：

### 0.1 识别文档内核类型

扫描文档，判断主要内核（决定整体布局）和次要内核（决定局部组件）：

| 内核类型 | 信号特征 | 最佳可视化形式 |
|---------|---------|-------------|
| **流程型** | 步骤/阶段/如何做/操作指南/第一步第二步 | 步骤卡片（Step Cards）或 Sticky Scrollytelling |
| **对比型** | vs/优缺点/对比/区别/哪个更好/方案A方案B | 双列卡片或对比表格（高亮推荐列） |
| **时间线型** | 年份/历史/发展/演变/里程碑/路线图/Q1Q2 | 垂直时间轴（Timeline） |
| **数据型** | 百分比/增长率/数字密集/调查结果/指标 | Stat Cards + 数字计数动画 |
| **概念型** | 什么是/定义/原理/框架/模型/理论/介绍 | 卡片网格（Card Grid）+ 图标 |
| **叙事型** | 背景/问题/解决方案/结果/案例/故事 | 滚动叙事（Scrollytelling） |

大多数文档是**混合型**的——判断主内核（决定整体骨架）和次内核（决定局部组件）。

### 0.2 判断内容量与交互深度

- 内容要点 < 5 个 → 全部展示，无需折叠
- 内容要点 5-15 个 → 标签页（Tabs）或手风琴（Accordion）
- 内容要点 > 15 个 → 滚动叙事 + 锚点导航

### 0.3 选择视觉风格

根据文档的**语气和受众**选择风格，不要用通用模板：

- 技术文档/研究报告 → 简约专业（深色代码感，蓝紫主色）
- 产品介绍/方案提案 → 现代商务（白底卡片，品牌感强）
- 数据报告/分析 → 数据仪表盘（深色背景，数字突出）
- 教程/指南 → 友好清晰（暖色调，步骤感强）
- 故事/案例 → 沉浸叙事（大图背景，渐进揭幕）

**向用户展示你的分析结果**，例如：
> "我判断这是一篇**流程型**文档（主内核），包含**数据型**局部（次内核）。整体采用步骤卡片布局，数据部分用 Stat Cards 展示。视觉风格选择现代商务风。你觉得这个方向对吗？"

## Step 1：技术架构决策

### 必须遵守的技术约束

- **单文件 HTML**：所有 CSS 和 JS 内联，双击即可打开，无需服务器
- **零框架依赖**：不使用 React/Vue/Angular，只用原生 HTML/CSS/JS
- **字体**：通过 Google Fonts CDN 加载 Inter（正文）+ 可选标题字体
- **图表**：如需图表，使用内联 SVG 或 Chart.js CDN（仅在必要时）
- **兼容性**：支持 Chrome/Firefox/Safari/Edge 最新版

### 设计令牌系统（必须使用 CSS 自定义属性）

读取 `references/design-tokens.md` 获取完整令牌系统。核心结构：

```css
:root {
  /* 主色调（根据风格选择，见 references/color-palettes.md） */
  --accent-start: #667eea;
  --accent-end:   #764ba2;
  --accent-rgb:   102, 126, 234;
  
  /* 中性色、间距、圆角、阴影 */
  /* ... 见 references/design-tokens.md ... */
}
```

## Step 2：构建 HTML

### 必须包含的基础结构

```html
<!DOCTYPE html>
<html lang="zh-CN" data-theme="light">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>[文档标题]</title>
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
  <link href="https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600;700;800&display=swap" rel="stylesheet">
  <style>/* 所有样式内联 */</style>
</head>
<body>
  <div class="progress-bar" aria-hidden="true"></div>
  <!-- 固定导航（文档较长时） -->
  <!-- Hero 区块 -->
  <!-- 内容区块 -->
  <!-- 页脚 -->
  <script>/* 所有 JS 内联 */</script>
</body>
</html>
```

### 根据内核类型选择组件

读取 `references/components.md` 获取每种组件的完整 HTML/CSS 代码。

- **流程型** → Step Cards（带序号、顶部彩条、级联动画）
- **对比型** → Comparison Table 或 Side-by-Side Cards（推荐列高亮）
- **时间线型** → Timeline（左侧线条+圆点，交替左右布局）
- **数据型** → Stat Cards（带数字计数动画）+ 可选图表
- **概念型** → Feature Cards Grid（带图标、悬停效果）
- **叙事型** → Sticky Scrollytelling（左文字右图形，粘性固定）

### 必须实现的交互效果

1. **阅读进度条**：页面顶部，纯 CSS scroll-driven animation
2. **滚动进入动画**：IntersectionObserver + CSS transition，元素进入视口时淡入
3. **卡片悬停效果**：`transform: translateY(-4px)` + 阴影加深
4. **深色/浅色模式切换**：右上角按钮，切换 `data-theme` 属性
5. **数字计数动画**（数据型内容）：easeOutCubic 缓动，1.8s 完成

读取 `references/animations.md` 获取所有动画的完整代码。

## Step 3：质量自检清单

在输出 HTML 之前，逐项检查：

**内容完整性**
- [ ] 原文档所有信息都已包含，没有遗漏
- [ ] 标题层级清晰，信息架构与原文一致
- [ ] 关键数据/结论有视觉突出

**视觉质量**
- [ ] 主色调与文档语气匹配（不是随便选的）
- [ ] 字体层级清晰（标题/副标题/正文/标注至少 3 级）
- [ ] 间距系统一致（使用 CSS 变量，不是随意的 px 值）
- [ ] 卡片/区块有适当的阴影和圆角，不是生硬的方块

**交互体验**
- [ ] 进度条存在且工作正常
- [ ] 滚动动画流畅，不卡顿
- [ ] 深色模式切换正常，颜色对比度足够
- [ ] 移动端响应式（最小宽度 320px 可用）

**无障碍**
- [ ] 图片有 alt 属性
- [ ] 颜色不是唯一的信息载体
- [ ] 有 `prefers-reduced-motion` 媒体查询回退
- [ ] 焦点样式可见（`:focus-visible`）

**代码质量**
- [ ] 所有 CSS 使用设计令牌（CSS 变量），没有魔法数字
- [ ] JS 使用 IIFE 或模块模式，不污染全局命名空间
- [ ] 没有 `console.log` 遗留

## 反模式禁令

这些是让 HTML 看起来"AI 生成感"的典型特征，必须避免：

- **绝对不用** 紫色渐变配白色文字作为默认方案（太俗气）
- **绝对不用** Inter 字体 + 蓝色按钮 + 白色背景的默认组合（太平庸）
- **绝对不用** 每个段落都加 emoji 图标（视觉噪音）
- **绝对不用** 把所有内容都做成等高的卡片网格（忽视内容差异）
- **绝对不用** 动画过多导致页面"闪烁"（每个元素都在动）
- **绝对不用** 字体超过 3 种（视觉混乱）
- **绝对不用** 颜色超过 5 种（失去焦点）
- **绝对不用** 把 Markdown 直接渲染成 HTML（这不是可视化，是偷懒）

## 输出规范

最终输出一个完整的 `.html` 文件，保存到用户指定位置（或当前工作目录）。文件名格式：`[文档主题]-visual.html`。

同时向用户简要说明：
1. 识别到的内核类型和选择的布局方案
2. 使用了哪些主要组件
3. 如何在浏览器中打开（双击即可）
